# Contributing Guidelines

Thank you for contributing to the K8s LLM RCA Benchmark. We strive for a high bar of technical excellence and reproducibility.

## 🤝 Contribution Lifecycle

1. **Issue Identification**: Open a GitHub Issue for feature requests or bug reports.
2. **Branching**: Use a descriptive branch name (`feat/` or `fix/`).
3. **Local Validation**: Run the full benchmark suite locally:
   ```bash
   python eval/run_benchmark.py --incident data/incidents/INC-001
   ```
4. **Benchmarking Report**: PRs adding new models *must* include an updated `main_results.csv` generated by your changes.
5. **Pull Request**: Detail the technical impact and verify no regressions in Evidence Causal Sensitivity (ECS).


## 🛠️ Design Patterns

### Adding a New LLM Model
Models are integrated via the `ai/llm_engine.py` provider abstraction. 
- **NVIDIA NIM Integration**: Simply add the model UID to the `NVIDIA_MODELS` dictionary.
- **Custom Adapters**: If using a local model, implement the `generate()` method in `llm_engine.py`.

### Adding a New Domain
The framework is domain-agnostic. To add a new domain (e.g. Database, AWS Lambda):
1. Navigate to `data/cross_domain/`.
2. Model your incident after the `med.json` structure:
   - `chaos_metadata`: Higher-level prior.
   - `pod_logs`: Contradictory evidence lines.
   - `ground_truth`: Target diagnosis.

### Adding Chaos Scenarios
Chaos scripts reside in `infra/`. 
- Ensure your script includes a `cleanup()` function or is idempotent.
- Map the scenario name to a security level in `eval/run_benchmark.py`.

## 📜 Code of Conduct
We expect all contributors to adhere to the code of conduct standard for professional open-source projects.
