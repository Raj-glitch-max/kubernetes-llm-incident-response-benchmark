# ADR-002: IaC Tool — Terraform
Date: 2026-03-06 | Author: Raj | Status: Accepted

Context: Needed an Infrastructure as Code tool to define VPC, EKS, IAM, and monitoring resources reproducibly.

Decision: Terraform with modular structure (separate modules for vpc, eks, monitoring).

Alternatives:
- Pulumi: Smaller community, fewer module examples, less common in Indian DevOps job descriptions.
- AWS CDK: Vendor lock-in to AWS, less portable, TypeScript/Python overhead for infra-only work.
- Ansible: Better for configuration management than provisioning — used later for cluster config if needed.

Consequences:
✅ #1 IaC tool listed in Indian DevOps job descriptions
✅ Massive public module ecosystem (VPC, EKS modules already exist)
✅ Raj experienced — no learning curve
✅ Declarative — `terraform plan` shows exact changes before applying
⚠️ HCL syntax is unfamiliar to Soham (not relevant — Soham does not own Terraform)
⚠️ State management requires care (use S3 backend + DynamoDB lock for production)
