# ADR-006: Evaluation Methodology — Custom 4-Metric Framework
Date: 2026-03-06 | Author: Soham | Status: Accepted

Context: No standard benchmark exists for LLM-based Kubernetes RCA evaluation.
Needed a scoring methodology that is rigorous, reproducible, and produces publishable results.

Decision: Custom evaluation framework with 4 metrics:
1. RCA Accuracy — LLM predicted category vs ground truth category (0 or 1)
2. Hallucination Rate — LLM cited evidence not present in input (0 or 1 per incident)
3. Response Latency — time from prompt send to response received (ms)
4. Remediation Usefulness — would the suggested fix work on a live cluster (Y / N / Partial)

Alternatives:
- ROUGE score: Designed for text summarization comparison, not incident diagnosis accuracy.
  Would measure word overlap, not correctness of diagnosis — meaningless for this use case.
- Human evaluation only: Not reproducible. Cannot be automated in CI pipeline.
  Useful as a supplement but not as primary scoring method.
- Existing AIOps benchmarks: None cover live Kubernetes chaos with reproducible infra and public data.

Consequences:
✅ Novel methodology — original contribution to the field
✅ Fully automated — runs in GitHub Actions CI on every push
✅ Soham owns the design completely — clear ownership
✅ Results are comparable across models (same inputs, same scoring)
⚠️ Remediation Usefulness requires human judgment for Y/N/Partial — not fully automatable
⚠️ Accuracy scoring depends on category labels matching exactly — requires consistent ground truth labeling
